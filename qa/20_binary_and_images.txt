================================================================================
20 — Binary & Image Files
================================================================================

Covers: binary file detection, read-only placeholder, "READ ONLY" status
pill, Kitty graphics protocol image rendering.

--------------------------------------------------------------------------------

ID:       QA-BIN-001
NAME:     Binary file opens with placeholder (REGRESSION)
PRIORITY: P1
FEATURE:  binary
RELATED:  bugs.md P2 "Binary files should not be previewed"

SETUP
  Create a binary file: `dd if=/dev/urandom of=/tmp/zqa.bin bs=1024 count=4`.

STEPS
  1. ./zepto /tmp/zqa.bin

VERIFY
  - Buffer shows placeholder: "(Binary file — 4096 bytes)" or similar.
  - No garbage characters.
  - Typing and delete are blocked.

ID:       QA-BIN-005
NAME:     Detection uses first 8KB NUL scan
PRIORITY: P3
FEATURE:  binary detection

STEPS
  1. Create file with text first 16KB, then NUL bytes:
     `(head -c 16384 /dev/urandom | base64; printf '\0foo') > /tmp/zqa_mixed`
  2. Open.

VERIFY
  - Detected as binary (NUL detected in first 8KB of file content).

ID:       QA-BIN-006
NAME:     Image file opened on Kitty-capable terminal (REGRESSION)
PRIORITY: P2
FEATURE:  image
RELATED:  bugs.md P2 "Render images in terminal via Kitty graphics protocol"

SETUP
  Launch zepto inside Ghostty, Kitty, or WezTerm (`TERM_PROGRAM=ghostty`).

STEPS
  1. Open an image file (e.g. `./zepto /path/to/image.png`).

VERIFY
  - Editor renders the image inline in the editor area.
  - Aspect ratio preserved (not squashed).
  - Scroll / tab switch clears the image properly.
