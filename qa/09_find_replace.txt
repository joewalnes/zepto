================================================================================
09 — Find & Replace
================================================================================

Covers: Ctrl+F find mode, replace mode (Tab), regex toggle (⌃R), case
toggle (⌃C), capture groups ($0-$3), match count, next/prev navigation,
jump to first match.

--------------------------------------------------------------------------------

ID:       QA-FIND-001
NAME:     Ctrl+F opens find bar
PRIORITY: P0
FEATURE:  find

STEPS
  1. Open file with content.
  2. Press ⌃F.

VERIFY
  - Find bar appears at the bottom.

ID:       QA-FIND-028
NAME:     Replace preview: correct in-place text, no screen corruption,
          no document mutation (REGRESSION)
PRIORITY: P0
FEATURE:  replace preview
RELATED:  QA-FIND-005, QA-FIND-006, QA-REG-211
SCRIPT:   tier1/reg_211_find_replace_preview_no_mutation.sh

STEPS
  1. File contains `foo bar`, `foo baz`, `qux foo`, `hello world`.
  2. ⌃F, type `foo` (3 matches), Tab to replace field, type `X`, `Y`, `Z`
     one keystroke at a time.
  3. Escape (cancel), wait briefly, then ⌃Z.
  4. Reopen ⌃F, type `foo`, Tab, type `REPL`, Enter (real Replace-All).

VERIFY
  - After each replace-field keystroke, the preview shows the replacement
    substituted IN PLACE with the rest of the line intact — e.g. typing
    "XYZ" against `foo bar` shows `XYZ bar`, never `fooXYZ` (the seed
    "foo" left over from Tab-prepopulation concatenated with the typed
    text instead of being replaced by it).
  - Exactly one find-bar row and one copy of the current preview text are
    on screen at a time — no stacked duplicate rows accumulating from
    earlier keystrokes (this occurred on terminals narrower than ~90
    columns, including the common 80-column default, before the fix).
  - After Escape, the original file content is restored exactly and ⌃Z
    reports "Nothing to undo" — the preview never pushes real edits onto
    the undo stack, matching FindEngine.pm's "Virtual - doesn't modify
    document" contract.
  - A real Replace-All (Enter, not just preview) still works correctly
    and is fully undoable back to the original content.

ID:       QA-FIND-029
NAME:     Find bar shows which replace mode is active (Rep All: / Rep One:)
PRIORITY: P2
FEATURE:  replace mode indicator
RELATED:  QA-REG-217
SCRIPT:   tier1/reg_217_find_replace_mode_indicator.sh

STEPS
  1. ⌃F, type a search term, Tab to replace field.
  2. Observe the label to the left of the replace field.
  3. Press Shift+Tab once (toggles Replace All -> Replace One).
  4. Observe the label again.
  5. Open the command palette (⌃Space), search "Replace All Mode", run it.
  6. Observe the label a third time.
  7. Click directly on the label (mouse).

VERIFY
  - The label reads "Rep All:" when Replace All mode is active (the
    default), styled like the regex/case toggle pills' active (colored)
    state.
  - After Shift+Tab, the label reads "Rep One:" instead, styled like the
    toggle pills' inactive (dim) state — this is the actual fix: before
    it, there was no on-screen difference at all between the two modes,
    and no way to discover the mode without reading source code.
  - The command palette's "Replace All Mode" entry shows an "[on]"/"[off]"
    state matching the current mode, and running it toggles the label the
    same way Shift+Tab does (opening Find and Replace first if it wasn't
    already active).
  - Clicking directly on the label toggles the mode the same way, without
    needing Shift+Tab's key combo at all.
  - At no terminal width does adding this label cause the find bar to
    overflow — verified at both the common 80-column default and a
    narrower 76-column terminal (this find bar has a very tight width
    budget; see bugs.md's FIXED writeup for why a separate pill widget
    was tried first and reverted after it broke the P0 overflow-guard
    tests at these exact widths).
