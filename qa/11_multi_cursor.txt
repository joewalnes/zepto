================================================================================
11 — Multi-cursor Editing
================================================================================

Covers: Ctrl+D select-next-occurrence, typing affecting all cursors,
Esc/arrows clearing multi-cursor mode, status bar cursor-count indicator.

--------------------------------------------------------------------------------

ID:       QA-MC-001
NAME:     First Ctrl+D selects word under cursor
PRIORITY: P0
FEATURE:  multi-cursor

SETUP
  File with "foo bar foo baz foo".
  Cursor inside the first "foo" (col 2).

STEPS
  1. Press ⌃D.

VERIFY
  - "foo" is selected (word under cursor).
  - Status bar shows "1 cursor" indicator (or does not change).
  - Only one cursor, not yet in multi-cursor mode.

ID:       QA-MC-015
NAME:     Backspace across a line-join keeps every cursor correctly
          positioned (REGRESSION)
PRIORITY: P1
FEATURE:  multi-cursor edit / line-join
CROSS-REF: QA-REG-203 (qa/scripts/tier1/reg_203_multicursor_linejoin_desync.sh)

SETUP
  File:
    PREFIX
    ab.ab
  Cursor on line 2.

STEPS
  1. ⌃D, ⌃D — selects both "ab" occurrences on line 2 (2 cursors).
  2. Type "Z" (replaces both selections with "Z", giving "Z.Z").
  3. ⌫ ⌫ — first backspace collapses "Z.Z" to "" (no join yet); second
     backspace joins the now-empty line 2 into "PREFIX".
  4. Type "Q".

VERIFY
  - After step 3, only one line remains: "PREFIX", and the joining
    cursor sits at col 7 (right after the X).
  - After step 4, BOTH cursors' typed "Q" lands after "PREFIX"
    ("PREFIXQQ") — not one correct append plus one stray insert into the
    MIDDLE of "PREFIX" (the pre-fix bug produced "QPREFIXQ": the
    bystander cursor's line was adjusted for the join but its column
    was not, landing it at col 0 instead of col 7).
  - Discoverable: this is a natural consequence of the always-available
    Ctrl+D + typing + Backspace flow — no separate command needed.

ID:       QA-MC-016
NAME:     Backspace over a multi-line selection keeps other cursors on
          the correct (post-delete) line (REGRESSION)
PRIORITY: P1
FEATURE:  multi-cursor edit / multi-line selection
CROSS-REF: QA-REG-204 (qa/scripts/tier1/reg_204_multicursor_multiline_selection_desync.sh)

SETUP
  File:
    row0
    row1
    row2
    ab.ab
  Cursor on line 4 ("ab.ab").

STEPS
  1. ⌃D, ⌃D — selects both "ab" occurrences on line 4 (2 cursors).
  2. Click at the start of line 1, then Shift+Click at the end of line 3
     — gives the primary cursor a fresh selection spanning lines 1-3.
     (Confirms the secondary cursor from step 1 survives a click +
     shift-click — only arrow-key navigation and Escape clear
     multi-cursor mode.)
  3. Press ⌫.

VERIFY
  - Lines 1-3 ("row0"/"row1"/"row2") are gone; the surviving line reads
    ".ab" (the secondary cursor's own selected "ab" was also deleted, in
    the same keypress).
  - The other cursor's status-bar position reports the correct
    (shifted-up) line number. Pre-fix, a multi-line selection delete
    skipped fixing up every other cursor entirely (the "same-line"
    column-shift math was never reached for a delete spanning >1 line),
    leaving the bystander cursor pointing at a line number that no
    longer existed in the shortened document (status bar showed line 4
    in a 2-line document).
