ID:       QA-SBAR-020
NAME:     Compact pill form keeps toggle on/off color without a label
PRIORITY: P2
FEATURE:  sbar layout compact toggle

STEPS
  1. Open a non-prose file (e.g. `.dat`/`.py`, not `.txt`/`.md` — those
     default word wrap ON via Preferences::should_default_wrap) at a width
     where Word Wrap renders in compact form (icon/key only, e.g. default
     80 cols — see QA-SBAR-016). Screenshot it.
  2. Toggle word wrap on (⌥Z) — screenshot the compact pill again.
  3. Toggle word wrap off (⌥Z) — screenshot the compact pill again.

VERIFY
  - OFF: pill background is dimmed, matching the full-form OFF color.
  - ON: pill background is bright/highlighted, matching the full-form ON
    color — state is still conveyed by color alone even with no label text.
  - Automated script (`sbar_020_compact_toggle_color.sh`) only checks that
    the compact pill's underlying preference state is readable and
    correct on load — it does NOT script a toggle-then-reread round trip
    via the palette, because of `bugs.md` P2 "⌃Space can be silently
    dropped when it isn't the very first key sent" (unrelated pre-existing
    issue). The on/off color swap itself must be checked with the
    screenshot steps above, or via `hangon screenshot` manually.

ID:       QA-SBAR-021
NAME:     Compact pill form always shows an icon before the key, never a
          bare letter (REGRESSION)
PRIORITY: P2
FEATURE:  sbar layout compact icon
RELATED:  bugs.md "Discoverability sweep run 2" — QA-REG-173

STEPS
  1. Open a file with `--no-nerd-font`, at a width where a toggle pill
     (e.g. Word Wrap) renders in compact form (icon + key, no label — the
     default 80-col session already does this, see QA-SBAR-020).
  2. Observe the compact pill text.
  3. Repeat with nerd font enabled (default, omit `--no-nerd-font`).

VERIFY
  - The pill shows an icon character immediately before the key (e.g.
    `W Z` for Word Wrap: icon 'W', key 'Z'), in BOTH modes — never just a
    bare key letter with nothing in front of it.
  - This was investigated as a possible bug (an LLM-vision sweep flagged
    the compact Word Wrap pill as reading like a bare "Z") but did not
    reproduce against the actual character stream in either mode —
    confirmed via raw byte inspection and screenshot. It traced to the
    screenshot tool used by that sweep not having a patched Nerd Font
    glyph for one specific icon (`\x{f036}`) while rendering others fine
    — a font-completeness artifact of that tool, not a Zepto defect.
    `tests/renderer.t` "No priority > 0 command ever compacts to a bare
    key with no icon" is the general, whole-registry regression guard —
    it asserts this for every current and future status-bar-eligible
    command, not just Word Wrap.

ID:       QA-SBAR-022
NAME:     Status bar never overflows terminal width, even with
          multi-cursor or column-select indicators active (REGRESSION)
PRIORITY: P1
FEATURE:  sbar layout narrow-width multi-cursor column-select
RELATED:  bugs.md 2026-08-30 "Status bar overflow with multi-cursor /
          column-select indicators at narrow widths" — QA-REG-178,
          QA-REG-179

STEPS
  1. Open a file at 40x15 (file tree closed), with a realistic filename
     (~15-20 chars, e.g. `zdisc_check.demo.txt`).
  2. Confirm the baseline status bar (`1:1 ⌃G ... Commands ⌃␣`) fits
     cleanly with no wrap.
  3. Toggle column select mode (⌥C), then extend the selection down a
     few lines (arrow keys). Confirm the `COL n` indicator appears
     inline and the whole bar — cursor pill, COL indicator, Commands
     pill — still fits within 40 columns with no wrap/scroll/corruption.
  4. In a file with several repeated words, select multiple occurrences
     (⌃D repeated) to grow the multi-cursor count into double digits.
     Confirm no wrap/scroll occurs and, once the transient "N cursors"
     confirmation message clears (e.g. after typing), the persistent
     `N cursors` indicator (when visible) still fits within the terminal
     width.
  5. Repeat at 50x18, 60x20, 80x24.

VERIFY
  - The status bar's printable width (ANSI stripped) never exceeds the
    terminal's column count, at any tested width, for any combination of
    multi-cursor count / column-select state / nerd-font mode.
  - No terminal soft-wrap/scroll occurs — the tab bar and ruler row
    remain in place after every redraw.
  - Supplementary indicators (COL rect, multi-cursor count) degrade by
    dropping entirely when they don't fit — the cursor-position pill and
    the `Commands ⌃␣` palette trigger never drop (UI_GUIDELINES.md:
    the palette pill "must never be droppable by width or context").
  - See tests/renderer.t "Context status bar never exceeds terminal
    width: multi-cursor / column-select property sweep (QA-REG-179)"
    and the two other QA-REG-179 property tests alongside it for the
    automated regression coverage (swept across ~5000+ combinations of
    width, multi-cursor count, column-select state, nerd-font mode, and
    filename).
