The 6 entries below (QA-PERF-016 through QA-PERF-021) are the "not vision-
based" leg of this session's QA coverage expansion: a vision judge looking
at a single screenshot cannot tell you an operation took 3 seconds — that
needs real wall-clock timing, not pixel analysis. All 6 use the shared
`qa/lib/qa-perf-helpers.sh` helper (`qa_assert_perf`/`qa_perf_poll_for`),
which distinguishes SLOW (the expected result eventually appeared, just
late) from HUNG/BROKEN (it never appeared at all) in the failure message —
those need different follow-up. Thresholds are deliberately generous
(multi-second budgets on multi-thousand-line fixtures): the goal is
catching gross regressions and hangs, not micro-benchmarking.

ID:       QA-PERF-020
NAME:     Word wrap toggle on a large wrapped file completes within budget
PRIORITY: P2
FEATURE:  perf wrap, hang-detection
RELATED:  bugs.md's WrapMap Fenwick-tree perf fix (the O(remaining-lines)
          tail this check exists to catch a regression of)
SCRIPT:   tier1/perf_020_wrap_toggle_large_file.sh

SETUP
  5000 lines, each ~190 chars (guarantees wrapping at any reasonable
  terminal width); terminal explicitly pinned to 80x24.

STEPS
  1. Toggle word wrap on (⌥Z).

VERIFY
  - A wrap continuation indicator (↪) renders within 4s.

NOTES
  Two test-script pitfalls found and fixed while validating this script
  (not product bugs — see bugs.md's 2026-08-30 entry for both): (1) a
  `.txt` fixture defaults to wrap ON via `Preferences.pm`'s
  `WRAP_DEFAULT_EXTENSIONS`, flipping the toggle's expected direction —
  fixed by using `.dat`; (2) the ambient tmux window size isn't
  guaranteed, so lines that "should" wrap sometimes didn't on a wide
  default window — fixed by pinning the terminal size explicitly via
  `qa_resize_window`.
