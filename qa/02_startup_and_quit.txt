02 — Startup and Quit
================================================================================

Covers: initial render, alternate screen buffer usage, clean exit,
unsaved-changes prompt, terminal restoration on crash.

ID:       QA-STRT-001
NAME:     Startup under 100ms (first render)
PRIORITY: P1
FEATURE:  performance

STEPS
  1. Time the command: `time ./zepto /tmp/small.txt` (Ctrl+Q immediately).
  2. Use a separate timer if possible to measure time-to-first-render.

VERIFY
  - Time from launch to first visible render is under ~100ms on a
    typical machine.
  - No noticeable flash of unstyled content.

ID:       QA-STRT-002
NAME:     Alternate screen buffer does not clobber scrollback
PRIORITY: P0
FEATURE:  terminal

SETUP
  In a fresh terminal, run `ls -la` or similar to produce scrollback.

STEPS
  1. Run `./zepto`.
  2. Do some work (type, navigate).
  3. Press ⌃Q to quit.

VERIFY
  - After quitting, the terminal shows the previous `ls` output — the
    editor content did NOT persist to scrollback.
  - Cursor is positioned at the shell prompt, below the previous output.
  - No stray escape sequences visible.

Session Restore (bugs.md P2 "Session restore")
--------------------------------------------------------------------------------

Design: session state (open tabs, cursor, scroll) is saved per working
directory (keyed by cwd, not global) at quit time, and restored only when
zepto is launched with NO file/directory arguments. Explicit file args, or
a bare directory arg (tree-focus mode), always win over the saved session
and — critically — never overwrite or clear it, so a one-off `zepto
file.txt` or a `zepto .` tree-browse doesn't destroy a real saved session
for that directory. Only tabs with a real file path are saved; unsaved
`[untitled]` buffers are never persisted. Files that vanished since the
session was saved are skipped individually at restore. Gated by the
`restore_session` preference (default on), toggleable from the command
palette (⌃Space -> "Restore Session on Startup").

ID:       QA-SESS-001
NAME:     Basic session restore — tabs, active tab, cursor
PRIORITY: P1
FEATURE:  session restore

STEPS
  1. In a fresh project dir, `./zepto a.txt b.txt`.
  2. Move the cursor to a distinctive position in a.txt.
  3. ⌥. to switch to b.txt, move the cursor there too.
  4. ⌃Q to quit.
  5. Relaunch with NO arguments from the same directory: `./zepto`.

VERIFY
  - Both a.txt and b.txt tabs reappear.
  - b.txt (the tab that was active at quit) is the active tab.
  - Cursor position in both tabs matches where it was left.

ID:       QA-SESS-003
NAME:     Explicit file args bypass and never clobber a saved session
PRIORITY: P1
FEATURE:  session restore
RELATED:  QA-REG-115

STEPS
  1. Bare-launch `./zepto`, open a.txt and b.txt (⌃O), quit (⌃Q) —
     this saves a session for the directory.
  2. Launch `./zepto c.txt` (a file NOT in the saved session). Quit.
  3. Relaunch with no arguments.

VERIFY
  - Step 2 shows only c.txt — the saved a.txt/b.txt session is not
    opened alongside it.
  - Step 3 still restores a.txt and b.txt — the one-off c.txt launch in
    step 2 did not overwrite or clear the saved session.

--------------------------------------------------------------------------------

ID:       QA-SESS-004
NAME:     Directory-arg launch does not restore or clobber the session
PRIORITY: P2
FEATURE:  session restore
RELATED:  QA-REG-115

STEPS
  1. Bare-launch, open a.txt and b.txt, quit (saves a session).
  2. Launch `./zepto .` (directory arg — tree-focus mode). Quit
     immediately without opening any file.
  3. Relaunch with no arguments.

VERIFY
  - Step 2 shows a single empty `[untitled]` tab with the tree focused —
    it does NOT restore a.txt/b.txt.
  - Step 3 still restores a.txt and b.txt — browsing the tree in step 2
    did not wipe the saved session.
