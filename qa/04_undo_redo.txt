04 — Undo and Redo
================================================================================

Covers: undo stack, redo stack, edit grouping, interactions with save,

ID:       QA-UNDO-001
NAME:     Basic undo restores previous state
PRIORITY: P0
FEATURE:  undo

SETUP
  File with "hello".

STEPS
  1. Type ` world` — document becomes "hello world".
  2. Press ⌃Z.

VERIFY
  - Document reverts to "hello".
  - Cursor is repositioned to pre-edit position.
  - Dirty flag may still be set (edit happened, even if undone).

VERIFY

ID:       QA-UNDO-013
NAME:     Cursor stays within valid line numbers across undo and redo
PRIORITY: P0
FEATURE:  undo redo cursor-bounds

SETUP
  A 3-line file:
      alpha
      beta
      gamma

STEPS
  1. Select all three lines (⇧↓, ⇧↓, ⇧End) and press ⌃C.
  2. Go to the end of the document (⌃G → 3 → Enter, then End).
  3. Press ⌃V. The document grows to 5 lines and the cursor lands on
     line 5 — below the document's ORIGINAL last line.
  4. Press ⌃Z. The document shrinks back to 3 lines.
  5. Press Escape so the transient "Undo" message clears and the status
     bar's line:col indicator is visible again.
  6. Type a character.
  7. Press ⌃Z, ↓, then ⌃Y.

VERIFY
  - After step 5 the status bar reports a line between 1 and 3. It must
    NOT report line 4 or 5 — a line number greater than the document's
    line count is the bug this test exists for (QA-REG-230).
  - After step 6 the typed character appears on the line the status bar
    reported, not on some other line. Before the fix the status bar said
    line 5 while the character was silently inserted on line 3, because
    the offset lookup saturates at the last real line.
  - The redrawn line is not visually truncated or mangled.
  - After step 7 the cursor is still within the document's line range.
  - The same holds for the selection anchor and for every extra cursor
    when multi-cursor mode is active.

NOTES
  The paste MUST leave the cursor below the document's original last
  line, otherwise the post-undo cursor happens to be in range anyway and
  the test proves nothing. Pasting at the top of the document does not
  reach this bug.

  Automated coverage: qa/scripts/tier1/reg_230_undo_cursor_bounds.sh
  (interactive), tests/undo_redo_cursor_bounds.t (23,880-permutation
  sweep), tests/editor.t 'Cursor stays in bounds across undo/redo'
  (real command path).

ID:       QA-UNDO-014
NAME:     New edit clears redo stack (typed-suffix variant)
PRIORITY: P2
FEATURE:  redo
RELATED:  QA-UNDO-006 (same behavior, single-character fixture)
SCRIPT:   tier1/undo_014_redo_stack_after_second_edit.sh

SETUP
  A file containing "original".

STEPS
  1. Move to end of line, type " first".
  2. Press ⌃Z (undo — removes " first").
  3. Type " second".
  4. Press ⌃Y (redo).

VERIFY
  - ⌃Y has no effect — "first" does not reappear anywhere on screen.
  - "second" remains the visible suffix (the new edit, not the undone
    one, is what's on screen).

NOTES
  This script previously collided with QA-UNDO-010's ID (both claimed
  "010" — see bugs.md's QA catalog ID-collision hygiene entry) and tests
  materially the same behavior as QA-UNDO-006 with a multi-char-suffix
  fixture instead of QA-UNDO-006's single-character one. Kept as a
  distinct (if narrow) regression check rather than deleted, since it was
  already a working, passing script; a future consolidation pass could
  fold it into QA-UNDO-006 as a second scenario.

ID:       QA-UNDO-015
NAME:     Undo stack behavior after command-palette forced reload
PRIORITY: P2
FEATURE:  undo reload
RELATED:  QA-UNDO-011 (external-modification-detected reload, not a
          user-forced command)
SCRIPT:   tier1/undo_015_force_reload_command.sh

SETUP
  Open file, make an edit (undo stack now has an entry).

STEPS
  1. Modify the buffer (type " modified").
  2. Open the command palette (⌃Space) and invoke "reload" directly
     (not triggered by an external file change).
  3. Confirm the reload prompt if one appears.
  4. Press ⌃Z.

VERIFY
  - Editor remains alive and responsive after the forced reload + undo
    (no crash).
  - Undo either does nothing (stack cleared by reload) or reverts
    gracefully — either is acceptable, but the process must not crash.

NOTES
  This is the command-palette-triggered reload path, distinct from
  QA-UNDO-011's external-file-change-detected reload path. Previously
  filed under QA-UNDO-011's ID by mistake (collision found and fixed —
  see bugs.md's QA catalog ID-collision hygiene entry).
