ID:       QA-PREF-014
NAME:     Persistent config file IS preferences.json (DOC CHECK)
PRIORITY: P3
FEATURE:  pref persistence
RELATED:  QA-PREF-015
RELATED:  QA-PREF-016
RELATED:  QA-PREF-017
RELATED:  QA-PREF-018
RELATED:  QA-PREF-019
RELATED:  QA-PREF-020

NOTES
  Resolved 2026-08-29 (see bugs.md P2 "Persistent config file"). This entry
  previously claimed no persistent config file existed and described the
  store as a sqlite-like $HOME/.local/share/zepto/state.store — both were
  stale/incorrect even at the time. The truth, confirmed by audit:

  - StateStore (lib/Zepto/StateStore.pm) has ALWAYS persisted preferences
    as human-editable, pretty-printed JSON at
    $XDG_CONFIG_HOME/zepto/preferences.json (default ~/.config/zepto/),
    honoring --state-dir / $ZEPTO_STATE_DIR (see build.pl). This IS the
    persistent config file — no second config system (e.g. config.toml)
    was introduced; that would have been needless duplication.
  - What was genuinely missing: several persist-eligible preferences had
    NO UI to change them at all (tab_width, soft_tabs, auto_indent,
    mouse_enabled), and two working preferences (search_wrap,
    render_markdown_tables) had a UI gap AND were not yet in the
    persisted set. All six were closed — see QA-PREF-015 through
    QA-PREF-020, each with a palette command and StateStore persistence.
  - A number of other defined preferences (show_line_numbers,
    show_status_bar, confirm_quit_unsaved, scroll_margin, backup_on_save,
    trim_trailing_whitespace, ensure_final_newline, search_case_sensitive,
    search_regex) are vestigial: the renderer/behavior never reads them,
    so persisting them would be misleading (nothing to persist). These are
    tracked as separate P3 bugs.md items — implement-or-remove, not a
    persistence problem. Deliberately out of scope here.

VERIFY
  - $ZEPTO_STATE_DIR/preferences.json (or --state-dir DIR/preferences.json)
    exists after any preference change, is valid pretty-printed JSON, and
    a hand-edit of it is picked up on next launch (or via cross-instance
    sync, QA-PREF-010).
