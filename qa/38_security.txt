================================================================================
38 — Security
================================================================================

Covers: shell injection (VCS/Git.pm, Terminal.pm), symlink traversal,
ReDoS protection (length + timeout), atomic save (File::Temp), terminal
escape sanitization in filenames, no network calls.

--------------------------------------------------------------------------------

ID:       QA-SEC-001
NAME:     No shell injection in VCS operations (REGRESSION)
PRIORITY: P1
FEATURE:  sec injection
RELATED:  bugs.md P1 "Shell injection in VCS/Git.pm"

SETUP
  Git repo; file named `foo; touch /tmp/zqa_pwned; bar.txt` (harmless
  marker for testing).

STEPS
  1. Open that file in zepto.
  2. Observe.
  3. Check /tmp.

VERIFY
  - `/tmp/zqa_pwned` does NOT exist (shell not invoked on filename).
  - Git operations use list-form exec, not backticks with interpolation.

ID:       QA-SEC-008
NAME:     No network calls made
PRIORITY: P1
FEATURE:  sec offline
CROSS-REF: qa/41_ai_completion.txt (full AI feature test plan)

SETUP
  Block network at OS level (or firewall zepto).

STEPS
  1. Full session: open, edit, save, find, all features, WITHOUT ever
     configuring or enabling AI completion.

VERIFY
  - Core editor works fully offline with zero network calls.
  - AI completion is the one sanctioned exception (see docs/SECURITY.md
    "Network: AI Completion"): ships disabled, requires the user to
    explicitly configure AND enable it (with endpoint-named consent) via
    "AI: Configure" / "AI Completion" in the command palette before any
    request is ever made.
  - No telemetry or background requests, ever, regardless of AI state.
